# DietApp 设计契约

来源：`docs/design/ui-bundle/`。`DietPhone.dc.html` 是产品 UI 真源；
`DietApp 三Tab.dc.html` 只贡献展示种子值和设计意图陈述，不是产品 UI；
`support.js` 是 Claude Design 画布工具自身的渲染引擎（dc-runtime），**不是
`frontend/` 可复用的代码或组件库**，只参考它渲染出的视觉结果，不参考实现方式。

**方向性声明**：bundle 是为了先敲定一版初步视觉方向做的原型，是参照不是定论，
后续视觉方向调整时数值和部分规则都可能变。

**token vs 业务数值**：bundle 里的时间、日期、体重、kcal、百分比、图表坐标点
都是 mock state 实时算出来的，不是设计常量，本文档不记录这些数值本身，只记录
"这类数据用什么字号/颜色/图表类型表现"。

**免责声明**：本文档数值是从 bundle 提炼的种子值；待 `frontend/` 建立 config
后，数值以 config 为准，本文档只保留语义角色和规则。

**标注**：`[硬规则]` = bundle 里所有实例一致执行的模式，供保持一致性参考，
不代表不可更改；`[软值]` = 观察到的具体数值，未来在 config 收敛。

## 1. 设计原则 / 风格基调

- 手机竖屏 390×844 唯一正式布局，桌面端复用同一组件结构，不做宽屏专属页
  `[硬规则]`（引用 `.claude/rules/frontend.md`）。
- 浅底衬深色文字、大留白、圆角卡片。
- 主色深植物绿；数据层五色语义分工（摄入/碳水/蛋白/脂肪/纤维），是产品级
  固定语义色，不做用户可调面板（bundle 里的 Tweaks 演示机制只是设计工具
  自身能力）。
- 数字一律 DM Sans，中文/UI 文案一律 Noto Sans SC `[硬规则]`。
- 界面结构镜像 PRD §4.2 / SPEC §2 的模块三分：记录=对话录入中心，
  看板=复盘中心，我的=设置中心。
- 对话输入优先于表单：底部常驻胶囊输入条是"记录"页唯一主入口。

## 3. 字号 / 字重层级

`[硬规则]` 数字/计量单位一律 DM Sans，中文和通用 UI 文案一律 Noto Sans SC，
无例外。

`[软值]` 字号按用途分组（种子值，非固定档位）：
| 用途 | 范围 |
|---|---|
| Hero 统计数字（常配负字距 -.8~-1.2px） | 26–34px |
| 次级统计数字 | 14–17px |
| 小标签数字（密集数据行） | 9.5–12px |
| 正文/交互文案 | 12–13.5px |
| 次要说明文案 | 10–11.5px |
| Kicker/eyebrow 小标签（宽字距 1–3px + 弱化色） | 9–11px |

字重：400 常规，500 轻度强调（选中态/数值），700 标题与 Hero 数字。
无 600/800 产品用例（`support.js` 原子类 CSS 有 `.fw6/.fw8`，属工具自身样式，
排除）。

## 4. 间距 / 圆角 / 阴影基础 token

### 圆角（`[软值]`，两个关键档位已拍板）
| 用途 | 值 |
|---|---|
| 微元素 | 2–4px |
| 标签/徽标 | 99px 胶囊 或 5–6px 方角（两种并存，按标签类型区分） |
| 控件/小按钮 | 8–11px |
| 分段控件轨道 | 10–13px |
| **标准卡片** | **20px** |
| **强调卡片** | **24px** |
| 设备外壳（非产品 token） | 44px |
| 完全圆形 | 50% / 99px |

标准/强调卡片圆角以实现（20/24px）为准；画廊文案自称"22px"是不准确描述，
已丢弃。

### 间距 `[软值]`
不是整齐的 4/8px 网格，观察值分布在 3–22px（3,4,5,6,7,8,9,10,12,13,14,16,
18,20,22…）。如实记录，是否收敛成标准网格留给 config 阶段，本文档不下结论。

### 阴影
见 §2 配色系统"阴影"一节。

## 5. 组件行为规则

- **主操作按钮**：实心 `#2E8B62` + 白字，悬停 `#22704E`，圆角 8–11px。
- **确认/提交按钮两态** `[硬规则]`：点击前实心绿底白字；点击后变浅灰底
  `#E2E9DF` + 灰字 `#657469` 且不再可点——已完成的操作用中性色回收，
  不再突出。bundle 无任何删除/危险操作可类推，"危险操作二次确认"视觉规则
  见 §7 Gaps。
- **次级/幽灵按钮**：透明底 + 1px 描边 `rgba(20,30,25,.20)` + 弱化文字
  `#7C8A82`，悬停铺浅灰 `#E6ECE3`。
- **分段控件**：轨道浅灰底；选中=白底+深色文字+字重 500+极轻阴影；
  未选中=透明底+弱化文字+字重 400。
- **多选筛选胶囊** `[硬规则]`：与分段控件是两种不同的选中态表达——outline
  风格，选中=该维度自身主题色描边 + 12% 透明度填充 + 深色文字。分段控件用
  白底+阴影表达选中，筛选胶囊用主题色描边+浅填充表达选中，两者不能混用。
- **开关（Switch）**：42×24 轨道，ON=`#5FCB96`，OFF=`#DFE4DE`，白色圆形
  knob 带轻阴影。
- **卡片**：白底 + 20px 圆角（Hero 24px）+ 极轻中性阴影，默认无描边，
  仅强调卡片加主题色浅描边（同 §2）。
- **数据来源徽标交互** `[硬规则]`：警示徽标必配"可能不准"文字，从不单独
  出现（同 §2）。
- **主输入方式** `[硬规则]`：底部常驻胶囊输入条，"记录"页唯一主要数据
  录入入口，对话输入优先于表单。
- **图表/可视化模式** `[软值/方向性记录]`（只记录图表类型选择，不记录
  bundle 里的具体数据点，那些是 mock 数据实时算出的）：
  - 半圆环（donut/arc）→ 单一进度指标（如目标完成度）
  - 柱状图叠加灰色顶部扣减段 → 可分解数值（摄入 − 运动消耗）
  - 折线图（等间距、非真实时间轴）→ 多指标趋势对比
  - 堆叠色块柱 → 占比构成（四大营养素）

## 6. 状态样式（loading / 空态 / 错误态）

- **空态**（bundle 部分覆盖，两种不同语境各自记录，不强行统一）：
  - 列表行级：餐次分组无记录 → 整行背景变浅（`#E8EFE6`→`#F3F6F1`），
    文案"未记录"（`#93A199`），展开箭头变浅（`#C6CFC8`）且不可点。
  - 字段级：单个身体维度字段缺失 → 显示"—"，颜色 `#A2AFA6`。
- **可复用的成功/待确认态**：§5"确认按钮点击后变灰"，可作为
  "待确认→已确认"类状态的参考。
- **Loading / 整屏空态 / 错误态**：产品 UI 无样例，见 §7 Gaps。

## 7. Gaps / 待补

bundle 里不存在，做对应界面时再设计，不阻塞本文档：

1. **危险色 / 错误色**：未定义，无产品 UI 实例。
2. **危险操作二次确认的视觉规则**：AGENTS.md 有文字规则，但 bundle 无
   删除/危险操作 UI，无法类推视觉样式。
3. **Loading 态**：产品侧空白。`support.js` 的骨架屏扫光动效是设计工具
   自身 chrome，明确排除，不作为产品参考。
4. **整屏空态**（如从未记录过、列表为空+引导文案/插画）：无样例，目前
   只有 §6 两种局部缺失值表达。
5. **错误/失败态视觉方案**：`.claude/rules/frontend.md` 已要求"写入交互
   必须呈现明确成功/失败/待确认状态，不能伪成功"——已知必须补，但 bundle
   无视觉方案，留到实现对应界面时设计。
6. **图标系统**：目前全是抽象占位形状（空心圆/方块/线条），无真实图标集。
