# 0005 — food_base_cn / food_base_us 数据源选型：试验阶段优先免费

**状态**：已接受
**日期**：2026-08-20
**关联**：SPEC §4.4（外部食物库）、[0002](0002-composed-dish-fallback.md)（已实测确认 food_base_cn/us 结构上只覆盖原型食物、不覆盖成品菜——本决策的选型不需要"能否覆盖成品菜"作为标准）、`docs/data/food_base-import-log.md`（版本锁定记录）

## 背景

食物成分数据是四级查询链②③级的基础，需要为 `food_base_cn`（中国来源）和 `food_base_us`（USDA 来源）选定具体数据源。项目当前处于试验/自用阶段（无收入、无付费用户、未对外分发），需要一条选型原则来判断"够不够用"，而不是逐个数据源单独评估、缺乏统一标准。

## 决策

**原则：试验阶段优先选免费/开源数据源，不引入付费数据服务**。具体到两个来源：

- **`food_base_cn`**：使用 [Sanotsu/china-food-composition-data](https://github.com/Sanotsu/china-food-composition-data)
  开源仓库（视觉模型 OCR《中国食物成分表》第六版数据），已按 SPEC §4.4.1 锁定到具体 commit 导入，见`docs/data/food_base-import-log.md`。授权风险已在 SPEC §4.4.1 记录（仓库无明确开源许可证，当前自用阶段可用，对外分发前必须重新核实），本决策不重复展开。
- **`food_base_us`**：使用 USDA FoodData Central 官方批量下载（免费，无需 API key），仅选 **Foundation Foods** + **Survey (FNDDS)** 两个数据集，明确排除：
  - `Branded Foods`——全是美国商超品牌预包装食品，解压后约 3.1G，体量远超需要，且和中国用户的家常餐食场景不相关。
  - `SR Legacy`——USDA 官方标注为已冻结的历史数据库，最后一次发布是 2018-04，不再更新；Foundation/FNDDS是现行维护的数据。

两个 USDA 数据集已实际下载并核实（见 `backend/data/food_base/food_base_us/` 下两个版本目录各自的
`MANIFEST.txt`）：Foundation 363 条真实记录（原始数组 395 项，其中 32 项是 USDA 导出文件自身的 JSON null 占位，已在导入逻辑里处理）、Survey 5432 条，两个数据集的 `fdc_id` 之间无交集——合计 5795 条，和`food_base_cn` 的 1656 条同一量级，规模可控。

**维护模型（两个来源统一）**：选择锁定快照而不是运行时接口，连带决定了 SQL 表本身的语义——`food_base_cn`/`food_base_us` 两张表都是"当前锁定版本的整体重建结果"，不是运行时按需累加的缓存。重新导入时（锁定了新版本、或某个来源新增了一份本地快照），对该来源当前锁定的全部本地文件重新解析清洗，整表覆盖写入，不做按主键的增量 upsert，也不允许新旧版本的行同时留在表里被查询到。例如 `food_base_cn` 目前只有一个来源目录，未来如果新增第二个来源（新增一份本地快照），导入时是把两份来源的数据合并清洗后整体覆盖写入表，而不是"旧来源的行原地不动、新来源的行追加进去"。本地磁盘上的历史版本目录仍按 §4.4.1/4.4.2 的约定保留不删除（用于追溯），这条只约束 SQL 表这一层。`food_base_us` 原计划里"按 `fdcId` upsert、天然幂等、无需拒绝重复导入"这类缓存式语义已按此原则去掉，改成和 `food_base_cn` 一致的整体覆盖式导入。

## 理由

1. 项目当前无收入，试验阶段没有理由为食物成分数据付费；USDA 官方批量下载本身免费、无需注册 key，覆盖Demo/MVP 阶段的原型食物查询需求已经足够。
2. `Branded` 和中国用户场景不匹配（美国商超品牌预包装食品），排除它不影响查询命中率，反而避免了一个体量远超需要的数据集拖慢导入/查询。
3. `SR Legacy` 是已冻结的历史数据，Foundation/FNDDS 是 USDA 当前维护的现行数据，没有理由继续依赖一份不会再更新的旧库。
4. [0002](0002-composed-dish-fallback.md) 已经实测确认：无论 `food_base_cn` 还是 USDA 的任一子数据集，
   结构上都只覆盖原型食物/原料，不覆盖成品中式菜肴——这意味着"这个数据源能不能查到成品菜"从来不是选型标准，四级链本来就是靠④级拆解处理成品菜的，选型只需要考虑"原型食物覆盖率 + 免费"两条，不需要额外评估成品菜覆盖率。

## 后续影响

- 对外分发/公开测试前，`food_base_cn` 的许可证问题需要重新核实（SPEC §4.4.1 已有此提示，不是本决策新增的义务，只是重申，避免以后被遗漏）。
